# GitHub Radar — 本地 Chrome 扩展

在浏览器里发现、分类、追踪 GitHub 开源项目，并用你自己的 AI Key 做商业分析。
**没有服务器、没有账号、没有云端数据库**：Token、Key、项目和历史快照都只存在这台电脑的浏览器里。

## 安装（约 30 秒）

1. 打开 `chrome://extensions`
2. 右上角开启「开发者模式」
3. 点「加载已解压的扩展程序」，选择本目录 `extension/`
4. 工具栏出现雷达图标，点击打开 Popup

无需 `npm install`，无需构建，改完源码在扩展页点一下「重新加载」即可。

## 第一次使用

1. Popup 右上角 ⚙ → 设置
2. 填入 GitHub Token（fine-grained，只需 **Public repositories: Read-only**）
   - 不填也能跑，但只有 60 次/小时，只够做一次小规模体验
3. 保存 → 回到 Popup → 「立即采集」
4. 采集分片执行（每片约 10–20 秒），页面会显示 `搜索中 3/8`、`采集中 45/147`
5. 想看到 **24h 增长**，需要等下一次采集（默认 6 小时间隔）产生第二条快照

## 功能

| 模块 | 实现 |
|---|---|
| 项目发现 | GitHub Search API，8 条查询：近 7 天新项目、近 30 天潜力项目、近期活跃成熟项目 + 5 个 AI/Web3 分类关键词 |
| 分类 | 20 个一级分类，关键词规则匹配（名称 4 分 / topics 3 分 / 描述 0.5 分），命中不了落「其他」 |
| 增长追踪 | 每次采集追加 Star/Fork 快照，计算 24h / 7d / 30d 增量、增长率、实际窗口时长与趋势标签 |
| 浏览与筛选 | 关键词搜索、分类、语言、Star 下限、5 种排序、分页 |
| 详情 | 基础信息、分类置信度、Star 历史曲线、最近快照、License、官网、GitHub 跳转 |
| 收藏 | 本地收藏，列表/详情都可操作 |
| AI 商业分析 | 需求、用户、变现、竞品、成熟度、二次开发、成本、MVP、风险、0–100 评分 + 置信度 + 证据 |
| 数据管理 | JSON 导出/导入、清空数据、本地数据量统计 |
| 配置 | GitHub Token、AI Base URL/Key/Model、采集间隔、单轮同步上限 |

## 增长是算出来的，不是猜的

每次采集对每个仓库写一条快照（只追加，不覆盖）。计算 24h 增长时：

```
目标时间 = 当前快照时间 - 24h
基准快照 = 不晚于目标时间的最近一条
容差     = 24h 窗口 12h，7d 窗口 24h，30d 窗口 72h
超出容差 → 该指标为 null，界面显示 —
```

所以：

- 第一次采集后所有增长列都是 `—`，这是正确状态，不会拿 Star 总量冒充增长
- 实际窗口会显示（例如「窗口 25.4h」），因为一天 3 次采集不可能正好 24 小时
- 趋势标签（新项目 / 快速增长 / 持续增长 / 高热度 / 增长放缓 / 长期热门）都基于快照和阈值

## AI 商业分析

设置里填入任意 OpenAI 兼容接口（DeepSeek、OpenAI、Moonshot、本地 Ollama 等）。保存时会向 Chrome 申请访问该域名的权限，换域名需要重新授权。

分析内容：解决的问题、目标用户、需求信号、盈利模式、竞品与差异化、技术成熟度、二次开发难度、可复用能力、还缺什么、基础设施成本、MVP 方向、风险、未知项。

评分固定 6 个维度并加权：

| 维度 | 权重 |
|---|---|
| 需求强度 | 25 |
| 竞争格局 | 20 |
| 变现路径 | 20 |
| 技术壁垒 | 15 |
| 落地成本 | 10 |
| 时机 | 10 |

界面会同时显示**置信度**、每个维度的**评分依据**、**证据**和**未知项**，并明确标注「AI 估算」。
提示词强制要求：没有材料依据就写「未知」，不得编造市场规模、竞品价格等数据。

分析结果与原始仓库信息分开存储（`analyses` 表），重新分析不会动快照与收藏。

## 数据与隐私

- 配置：`chrome.storage.local`
- 项目、快照、收藏、AI 结果：IndexedDB（数据库名 `github-radar`）
- Token / Key 不会发往任何自建服务器；AI 请求直接从浏览器发往你填的 Base URL
- 卸载扩展或清除浏览器数据会一起删除，**请用「导出 JSON」备份**
- 采样数据仅来自 GitHub 公开 API 与你自己触发的 AI 调用

## 定时采集的真实边界

- 使用 `chrome.alarms`，浏览器关闭后不再运行（这是 MV3 的硬限制）
- Service Worker 空闲约 30 秒会被回收，所以采集被拆成小片：每次唤醒处理少量仓库，进度写入 IndexedDB，下一分钟继续；中断后可恢复
- 浏览器启动或扩展安装时会重建定时器；采集间隔在设置中修改后立即生效
- 命中 GitHub 限流会记录重置时间并延后重试，不会狂刷

## 已知限制

- **没有 Trending 网页解析**：GitHub 没有 Trending API，解析 HTML 易碎且会拖进 DOM 依赖。当前用 Search API + 快照增长替代，更可靠；以后要加可放到 V1.5
- **分类是规则匹配**，会误判（例如描述里出现 "agent" 的 Web3 项目可能被归到 AI Agent）。人工改分类尚未做，AI 分类留给下一版
- **无 Token 时体验有限**：60 次/小时，首轮默认最多同步 120 个仓库，建议配置 Token
- 没有账号、云同步、多人协作、Telegram 推送
- 未打包上架 Chrome Web Store（当前按「加载已解压」使用）

## 开发

零构建：原生 ES Modules + 原生 CSS + IndexedDB，没有打包器、没有运行时依赖。

```bash
cd extension
npm test                 # node --test tests/
node scripts/check-extension.mjs   # 检查 manifest / 资源 / import 图 / 命名导出
```

在受限环境（不能 spawn 子进程）里运行单个测试文件：

```bash
node --test --test-isolation=none tests/growth.test.mjs
```

调试：`chrome://extensions` → 本扩展 → 「Service Worker」查看后台日志；Popup 和面板各自右键「检查」。

### 为什么不是 React + TS + Tailwind

V1 的目标是「装上就能用、改完就能重载」。零构建换来的是：没有依赖锁、没有打包失败、没有版本漂移，扩展目录本身就是可加载产物。核心逻辑全部是纯函数模块，已有测试覆盖；如果以后要上 React/TS，`src/core` 可以原样迁移，只需要重写 UI 层。
